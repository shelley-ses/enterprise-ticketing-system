# Troubleshooting & Operations Runbook

This operations runbook provides diagnostic workflows, root-cause analyses, and concrete recovery steps for common operational issues encountered in the **Enterprise Ticketing System**.

---

```bash
# Check status of all containers
docker compose ps

# Tail error logs across all services
docker compose logs -f --tail=50

# Test database connectivity
docker compose exec db mysqladmin ping -h localhost -p${MYSQL_ROOT_PASSWORD}

# Inspect Redis cache keys
docker compose exec redis redis-cli info memory
```

## 1. ClamAV Antivirus Daemon Timeouts & Failures

### Symptoms
* Client receives `500 Internal Server Error` during file upload with message: `"Unable to verify file security. Please try again later."`
* Logs in `attachment-service` report: `ClamAV Scanning failed with exception: Connection refused` or `Socket timeout`.

### Root Causes
1. **Container Startup Latency**: ClamAV downloads fresh virus signature databases (`freshclam`) upon initialization, which can take 60–120 seconds.
2. **Insufficient Memory**: ClamAV requires a minimum of **2.0 GB of RAM** to hold active virus definitions in memory. If Docker has constrained memory, the kernel OOM-killer terminates ClamAV.

### Recovery Steps
1. Verify ClamAV container status and memory usage:
   ```bash
   docker stats capstone-clamav
   ```
2. Check ClamAV startup logs:
   ```bash
   docker compose logs -f capstone-clamav
   ```
   *Wait until you see:* `SelfCheck: Database status OK.`
3. Verify socket reachability from `attachment-service`:
   ```bash
   docker compose exec attachment-service php -r "
   \$fp = @fsockopen('clamav', 3310, \$errno, \$errstr, 5);
   echo \$fp ? 'Connected to ClamAV socket!' : 'Failed: ' . \$errstr;
   "
   ```

## 2. WebSocket & Reverb Connection Drops

### Symptoms
* Ticket status updates, notifications, or chat messages do not appear in real-time.
* Browser developer console displays continuous WebSocket reconnection attempts: `WebSocket connection to 'ws://localhost/app/...' failed`.

### Root Causes
1. **Nginx Missing Upgrade Headers**: Reverse proxy failed to pass HTTP `Upgrade: websocket` or `Connection: "Upgrade"`.
2. **Reverb Port Confusion**: Reverb uses **Port 6001** for core ticket events and **Port 6002** for live messaging.

### Recovery Steps
1. Verify Reverb container logs:
   ```bash
   docker compose logs -f reverb
   docker compose logs -f messaging-reverb
   ```
2. Confirm Nginx WebSocket proxy configuration in `nginx.conf`:
   ```nginx
   location /app/ {
       proxy_pass http://reverb:6001;
       proxy_http_version 1.1;
       proxy_set_header Upgrade $http_upgrade;
       proxy_set_header Connection "Upgrade";
   }
   ```
3. Test WebSocket handshake using `curl`:
   ```bash
   curl -i -N -H "Connection: Upgrade" -H "Upgrade: websocket" \
     -H "Host: localhost" -H "Origin: http://localhost" \
     http://localhost/app/local
   ```

## 3. Asymmetric RSA & OAuth Key Mismatches

### Symptoms
* Frontend reports `Error: Encryption failed` when attempting to log in.
* Valid user credentials return `401 Unauthorized` on `ticket-service` or other downstream microservices.

### Root Causes
1. Downstream services (`ticket-service`, `analytics-service`) are missing `storage/oauth-public.key`, or their local copies do not match the public key generated by `customer-service`.
2. Asymmetric key file permissions prevent the web server from reading the key.

### Recovery Steps
1. Regenerate or verify keys inside `customer-service`:
   ```bash
   docker compose exec customer-service php artisan passport:keys --force
   ```
2. Copy `oauth-public.key` from `customer-service` to consumer services:
   ```bash
   # Copy public key into ticket-service
   docker compose exec -T customer-service cat storage/oauth-public.key | \
     docker compose exec -T ticket-service sh -c "cat > storage/oauth-public.key"

   # Copy public key into analytics-service
   docker compose exec -T customer-service cat storage/oauth-public.key | \
     docker compose exec -T analytics-service sh -c "cat > storage/oauth-public.key"
   ```
3. Ensure proper file permissions:
   ```bash
   docker compose exec ticket-service chmod 600 storage/oauth-public.key
   ```

## 4. Multi-Service Database Migration Desynchronization

### Symptoms
* `PDOException: SQLSTATE[HY000] [1045] Access denied` or `Table 'clients' doesn't exist`.
* Foreign key constraint errors when migrating `ticket-service`.

### Root Causes
In a microservices ecosystem sharing a MySQL instance, services have dependency order requirements:
* `customer-service` owns `clients` and `employees`.
* `ticket-service` relies on `clients.id` and `employees.id` for foreign keys.

### Recommended Migration Sequence:
```bash
# 1. Customer service migrations (Base Identity Tables)
docker compose exec customer-service php artisan migrate --force

# 2. Ticket service migrations (Tickets, SLAs, Work Logs)
docker compose exec ticket-service php artisan migrate --force

# 3. Attachment service migrations (Proof, Attachments)
docker compose exec attachment-service php artisan migrate --force

# 4. Analytics service migrations (CSAT, Metrics)
docker compose exec analytics-service php artisan migrate --force
```

## 5. Stale Redis Query Cache

### Symptoms
* Newly created or assigned tickets do not show up on the Customer Support (CS) dashboard.
* Dashboard counters remain unchanged despite state updates.

### Recovery Steps
1. Purge ticket dashboard cache via Artisan:
   ```bash
   docker compose exec ticket-service php artisan cache:clear
   ```
2. Flush Redis cache keys directly via Redis CLI:
   ```bash
   docker compose exec redis redis-cli -a secret --scan --pattern "*cs_dashboard*" | \
     xargs -I {} docker compose exec redis redis-cli -a secret del {}
   ```

## 6. Nginx 502 Bad Gateway / FastCGI Errors

### Symptoms
* API requests return `502 Bad Gateway`.
* Nginx error log reports: `connect() failed (111: Connection refused) while connecting to upstream`.

### Recovery Steps
1. Check Nginx error logs:
   ```bash
   docker compose logs --tail=50 nginx
   ```
2. Identify the failing upstream container from the log (e.g., `fastcgi_pass ticket-service:9000;`).
3. In local development (`docker-compose.yml`), services run `php artisan serve` on port **8000**, whereas in production (`docker-compose.prod.yml`), services run `php-fpm` on port **9000**.
4. Confirm port matching between `docker-compose.yml` and `nginx.conf`.
